# Подключение к живому FACT и 1С

Всё, что нужно, чтобы завтра приложение заработало само: доска на мониторах
живая, тикеты и андон заводятся без людей, смены и остановы дописываются в базу,
заказы приходят из 1С. Код для этого готов и проверен на зеркале — тот же код
читает FACT по сети, меняется только источник.

## Перед подключением — 10 минут

1. Скопировать `_app\config.example.json` в `_app\config.json` и вписать:
   - `fact` — адрес FACT (`http://172.0.30.9`);
   - `looms` — сколько станков должно быть в FACT (40, потом 80);
   - `telegram.token` и `telegram.chat_id` — бот мастеров (как получить — в README);
   - `onec.url` и `onec.token` — если 1С будет отдавать заказы по адресу (см. ниже).
2. Выдать ключ для 1С: приложение → «Настройки» → «Ключи API» → «Для кого: 1С»,
   право «присылать заказы». Ключ показывается один раз — сразу передать
   программисту 1С вместе со ссылкой `http://<сервер>:8780/api/docs`.
3. Поставить автозапуск (от администратора):

   ```
   powershell -ExecutionPolicy Bypass -File _deploy\install_autostart.ps1 -Fact http://172.0.30.9
   ```

## Подключение — по шагам

| Шаг | Что сделать | Как понять, что получилось |
|---|---|---|
| 1 | `python _app\golive.py --fact http://172.0.30.9` | в разделе «FACT» все строки «ок»: сервер отвечает, станков столько, сколько ждали, снимок свежий |
| 2 | Перезапустить задание «Цех — приложение» (или `python _app\app.py`) | `http://<сервер>:8780/api/health` — `"ok": true`, в `checks.fact` «ок, снимок N с назад» |
| 3 | Открыть `/wall` на одном мониторе | внизу «живые данные FACT · связь: онлайн»; время простоя тикает |
| 4 | Подождать 2–3 минуты | стоящий дольше 2 минут станок без сигнала стал фиолетовым «нет тикета», в «Тикетах» появился автотикет |
| 5 | Нажать на такой станок, выбрать «Вызов электрика» (нужен вход) | плитка стала синей на всех мониторах сразу, без перезагрузки |
| 6 | Через 5 минут открыть «Простои» → «Сводка по причинам» и «По дням» за сегодня | сегодняшний день есть — сборщик дописывает остановы каждые две минуты |

## 1С: два способа, выбрать удобный программисту

**1С шлёт сама** — `POST http://<сервер>:8780/api/v1/1c`, заголовок
`Authorization: Bearer <ключ>` (или `X-Api-Key: <ключ>`; ключ с правом `write` выдаёт
админ во вкладке «Пользователи»). Тело — конверт 1С как есть:

```
{"actionType": "CreateOrUpdateProductionOrderAPI", "wait": true, "waitTimeout": 60000,
 "data": {"productionOrders": [{"orderNumber": 1708, "productCode": "220100 TerryCloth 390",
   "gsm": 390, "weight": 0.858, "weftPerOneRow": 1459, "sizeInfo": {"numberLines": 1}, ...}]}}
```

Ответ приходит сразу, 1С смотрит на `success`:

```
{"success": true, "actionType": "CreateOrUpdateProductionOrderAPI", "cards": 1, "yarns": 3,
 "yarns_added": 0, "looms": 14, "plan": {"orders": 1}, "report_days": ["2026.09.12"]}
{"success": false, "error": "неизвестный actionType «…»"}      — код 400
{"success": false, "error": "нужен ключ API: …"}              — код 401
```

Что берём из заказа: GSM (`gsm`), вес штуки (`weight`), PPT (`weftPerOneRow`),
панели (`numberLines`), количество, пряжу по типам. Пряжа «16/1 Ring Иштихан Суровый
Ворс 630 Лот №41» раскладывается на «16/1 RING» (сразу в справочник пряжи) и лот 41.
Станки (`workCenters`) — это где изделие *можно* делать, на станки заказ ставит план цеха.
Повторная отправка того же заказа обновляет его. `/api/v1/production-orders` принимает то же.

**Что прислала 1С — `GET /api/v1/1c`** (ключ с правом `read` или вход в приложение).
Каждый заказ хранится последней версией ровно так, как его прислала 1С, и отдаётся в
том же конверте `{"actionType": …, "data": {"productionOrders": [...]}}` плюс
`received` — когда пришёл, сколько раз присылали. Отбор: `?order=1708`,
`?from=2026.09.14`, `?limit=100`. Все сообщения целиком (и с ошибками) — во вкладке
«План» → «Сообщения из 1С». Из заказа отчёт берёт GSM, дизайн, вес, PPT, пряжу и лоты.

**План цеха** — Excel «TOYOTA - LOOM PLAN» грузится во вкладке «План» → «Загрузить план
из Excel». Из него — какой заказ на каком станке в какой день. Тогда отчёт за день сам
берёт PPT, вес, GSM, пряжу и лот из техкарты 1С этого заказа, а готовность заказа
считается по станкам и дням плана — связывать коды ткани не нужно.

**Мы забираем сами** — в `config.json`:

```
"onec": {"url": "http://1c-server/.../production-orders", "token": "Basic ...", "every_min": 30}
```

Сборщик раз в полчаса забирает заказы и раскладывает их в техкарты и план.

**Попросить у 1С два поля**, без них план работает хуже:

- `weftPerOneRow` — пики на изделие. Сейчас пусто во всех десяти техкартах, поэтому
  PPT считается по счётчикам станка или вводится руками («План» → «Пики на изделие»);
- `clothCode` — код ткани, как его набирают на станке (`3050X7360`). Без него связку
  «код на станке → артикул 1С» делают руками один раз: «План» → «Коды ткани…».

## Мониторы

Каждому экрану — свой участок, иначе 80 плиток с трёх метров не прочитать:

```
msedge --kiosk "http://<сервер>:8780/wall?zone=D" --edge-kiosk-type=fullscreen
msedge --kiosk "http://<сервер>:8780/wall?looms=J1-J14" --edge-kiosk-type=fullscreen
msedge --kiosk "http://<сервер>:8780/cards?zone=D" --edge-kiosk-type=fullscreen
```

Мониторы входа не требуют. Обновляются сами: сервер толкает доску, как только
пришёл снимок FACT или кто-то завёл тикет. Если сеть режет долгие соединения —
доска сама переходит на опрос раз в 15 секунд, внизу это видно: «связь: переподключение».

## Что работает само

| Как часто | Что происходит |
|---|---|
| каждые 5 секунд | сборщик спрашивает FACT, нет ли нового снимка станков |
| раз в минуту (как FACT) | новый снимок → доска на всех мониторах, автотикеты, андон |
| через 2 мин простоя без причины | «нет тикета» на доске |
| через 10 мин | тревога на доске: плитка мигает, красная строка сверху |
| через 15 мин | мастеру в телеграм, один раз на останов |
| каждые 2 минуты | дописываются смены и остановы, пересчитывается свёртка для отчётов |
| как пришла смена | производственный отчёт (лист TOYOTA) за этот день собирается сам |
| раз в полчаса | заказы из 1С (если задан адрес) |
| через 15 минут после смены | сводка по смене в телеграм; после смены C — итог за сутки |
| если FACT молчит 30 минут | тревога в телеграм, на доске — «данные не живые» |

Пороги андона меняются в «Настройках» и сразу действуют на всех досках.

## Если что-то не так

| Что видно | Почему | Что делать |
|---|---|---|
| На доске жёлтая строка «Данные не живые» | FACT не отвечает или не выкладывает снимки | `golive.py --fact …`; проверить сеть до FACT; `/api/health` покажет последнюю ошибку |
| «связь: переподключение» внизу доски | прокси или антивирус рвут долгие соединения | доска работает опросом; добавить сервер в исключения прокси |
| 1С получает 401 | ключ не тот или отозван | выдать новый в «Настройках» |
| 1С получает 403 | у ключа нет права «присылать заказы» | выдать ключ с этим правом |
| В плане «сделано 0» | код ткани на станке не связан с артикулом | «План» → «Коды ткани…» → связать |
| Андон не пишет в телеграм | не настроен бот или порог 0 | `config.json` и `golive.py --telegram` |
| Сборщик «не работает» в `/api/health` | упал или запущен второй экземпляр | журнал `_app\logs\app.log`; перезапустить задание |

## Как откатиться

Остановить задание «Цех — приложение» и запустить `python _app\app.py --mirror` —
приложение вернётся к работе по зеркалу. Люди ничего не теряют: тикеты, план,
пользователи и ключи лежат в `shop.db`, базу станков можно пересобрать из зеркала.
