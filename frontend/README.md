# Отчёт MES на React

Эталон — текущий HTML-отчёт MES. Сохраняются его CSS, плотность таблицы,
45 колонок, группы A/B/C, пороги окраски, подсказки, фильтры, сортировка,
итоги, заправка, периодные отчёты, утверждённые документы и Excel.

Адрес `/next/#report` загружает исходную `_app/ui.html` и собранный React-модуль.
React заменяет содержимое панели управления, таблицы, плиток итогов и полосы
полноэкранного режима, окно заправки, период и подтверждение документов отчёта.
Загрузкой отчёта, подготовкой строк,
фильтрами и сохранением настроек управляет `ReportController`. Меню, авторизация,
темы, перевод, общий подбор пряжи и журнал документов пока обслуживаются
исходным кодом через `FactReportLegacy`. Это постепенный
перенос одного экрана; остальные разделы ещё не переписаны на React.

## Запуск и проверки

Проверенная среда: Node 24, pnpm 11.25.0, Python 3.12. Из `frontend`:

```text
pnpm install --frozen-lockfile
pnpm check
```

`check` выполняет тесты Vitest, TypeScript и сборку Vite. Из корня репозитория:

```text
python _tools/check.py
python _tools/react_sandbox.py
```

Открыть http://127.0.0.1:8791/preview-login — временная локальная сессия на
синтетической SQLite. Исходный экран: http://127.0.0.1:8791/#report,
React: http://127.0.0.1:8791/next/#report. Оба используют одинаковые данные.
FACT, рабочие базы и сборщик не используются. Разрешены проверка и проведение
документов и создание тестового Excel — только во временных базах и каталогах.
После проведения заправки выполняется настоящий пересчёт отчёта. Источник смен
синтетический; архивные проверки PPT отключены. Ctrl+C останавливает сервер.

`pnpm dev` пересобирает модуль при изменениях (`vite build --watch`). Просмотр
через Python на 8791 с обновлением страницы; самостоятельный HTML Vite не содержит
оболочку MES. Node нужен для сборки, а не для работы приложения в цехе.

## Модули

- `src/mount.tsx` — подключение к исходной оболочке и обновления от неё.
- `src/features/report/model.ts` — колонки, фильтры, сортировка, агрегация.
- `src/features/report/Cell.tsx` — значения, окраска, ручные данные, подсказки.
- `src/features/report/controller.ts` — запросы, отмена и защита от устаревших
  ответов, выбор завершённого дня, подготовка строк и сохранение настроек.
- `src/features/report/SetupDialog.tsx` — форма заправки и подготовка документа.
- `src/features/report/ReportWorkflow.tsx` — период, проверка/проведение и Excel.
- `src/features/report/DocumentBody.tsx`, `period.tsx` — исходная разметка диалогов.
- `src/features/report/http.ts` — общая обработка API, ошибок и истечения сессии.
- `src/features/report/Report.tsx` — таблица и органы управления.
- `src/test/legacy.ts` — независимый эталон: выполняет старый рендерер для тестов.

Фильтры и свёрнутые группы сохраняются прежним способом в localStorage.
Сессии и контроль прав остаются на сервере. При ошибке загрузки сохраняются
последние успешно полученные данные вместе с их датой. Формулы дневного отчёта не изменены.
Сравнительные тесты защищают поведение, но не заменяют проверку CSS в браузере.

`browser-check.mjs` содержит воспроизводимый автосценарий для CUA: передать
`checkReport(tab)` вкладку `/next/#report` чистой синтетической песочницы на 8791.
Он проверяет сохранение фильтров после перезагрузки, отмену заправки без потери
ввода, период, предупреждения и реальное скачивание Excel. Запускается через
`cua_repl`, отдельно от `pnpm check`; это не автономный браузерный CI.

## Перед выпуском

Полный `_tools/e2e_test.py` обязателен по `AGENTS.md`. Для него нужны локальные
фикстуры `13.mxl`, `order_1557.json` и подготовленная тестовая БД. Локальный
React-стенд не заменяет этот тест. Дополнительно сверить темы, языки, роли,
сохранение заправки, проведение периода, Excel и мобильный экран.

Linux deploy пока не собирает frontend. До переключения нужно добавить тесты
и сборку в проверку кандидата и доставлять `dist` из той же ревизии. Без сборки
`/next/` отвечает 503; основной `/` работает как раньше. Хук и рабочий сервер
этой миграцией не меняются.
