# Отчётность ткацкого цеха по данным Toyota FACT

Приложение работает двумя способами: по локальной копии данных FACT (без сети)
или по живому FACT — тогда сборщик сам дописывает смены и остановы, доска на
мониторах живая, тикеты и андон заводятся без людей.

**Подключение к живому FACT и 1С — по шагам в [GOLIVE.md](GOLIVE.md).**

## Что где лежит

| Папка | Что в ней |
|---|---|
| `factdata/` | зеркало сервера FACT: журналы остановов, смены, состояние станков |
| `_tools/` | скрипты, база и готовые страницы |
| `_tools/fact.db` | база: смены, отчёты по дням, справочник |
| `reports/` | готовые Excel-отчёты |

## Ежедневное обновление — одна команда

```
powershell -ExecutionPolicy Bypass -File _tools\update_all.ps1
```

Скрипт сам проверит, доступен ли сервер. Если нет — посчитает по зеркалу.
Чтобы заодно собрать Excel-отчёт за день:

```
powershell -ExecutionPolicy Bypass -File _tools\update_all.ps1 -Report 2026.09.12
```

## Страницы

Лежат в `_tools`, открываются двойным щелчком:

- `daily_report.html` — производственный отчёт в формате листа TOYOTA, выбор дня;
- `explorer.html` — разбор простоев с фильтрами по периоду, сменам, станкам, артикулам;
- `shift_view.html` — обход цеха: к какому станку идти после смены.

## Что нужно на сервере

- Python 3.10 или новее (использует только стандартную библиотеку);

## Лист Working по техническому заданию

```
python _tools\build_working_report.py 2026.09.11
```

Даёт 112 колонок: основные данные, пряжа из 1С, мастерицы и операторы по сменам,
эффективность A/B/C, блоки Vors / Utog / Karenoy / Other Stops (количество, время,
среднее время одного останова) и блок Manual Stop по категориям тикетов.

Среднее время одного останова считается как время остановов, делённое на их
количество, и выводится в секундах — как требует ТЗ.

## Техкарты из 1С

```
python _tools\tech_cards.py --file "апи_dpa (4).txt"
```

Берёт из ответа 1С размер, PPT (`weftPerOneRow`), число панелей (`numberLines`),
дизайн (`productCode`), плотность и пряжу по типам с номерами лотов:
Pile yarn → Vors, Ground yarn → Karenoy, Weft yarn → Utog 1,
E hem single → Utog 2, Fancy single → Utog 3, Fancy polyester → Utog 4.

Когда появится адрес службы 1С, тот же скрипт берёт данные по сети:
`--url http://адрес --token "..."`.

## Приложение цеха

```
python _app\app.py
```

Открывается на порту 8780 — с любого компьютера в сети цеха по адресу
`http://<IP сервера>:8780`. Ставка — 287 сум за 1000 пиков.

| Заправка | все станки одной таблицей, как в Excel: GSM, вес штуки, PPT, панели, пряжа ворса, грунта и утка с лотами. Enter — вниз, Ctrl+D — значение сверху, блок из Excel вставляется целиком, значение или строка протягиваются на отмеченные станки. Ниже — справочник пряжи: одно написание на одну пряжу |

| Расстановка | три документа на каждый день — смены A, B, C: мастер смены, мастерицы, какой оператор на каком станке. Заводятся сами каждое утро и заполняются прошлой такой же сменой; мастер правит, утверждает и печатает с местом для подписей |
| Операторы | справочник: код, имя, роль; импорт имён из FACT |
| Простои | один пункт меню, четыре вкладки (видны по правам): **Сводка по причинам** — период, смены, группа станков, структура потерь; **Обход смены** — станки смены по простою и главная потеря каждого, куда идти первым; **По дням** — сводка как Manual Stoppages Summary в LDS: Shed / Time / Prod Eff, длинные остановы по причинам и сколько осталось без причины; **Ленты станков** — история состояний по журналу Toyota и минутным снимкам FACT |

программиста — `http://<сервер>:8780/api/docs`.

### Доска для мониторов в цехе

```
http://<IP сервера>:8780/wall
```

Экран на стене показывает станки: что работает, что стоит, сколько уже стоит
и по какой причине. Обновляется сам и сразу: сервер толкает доску, как только
пришёл снимок FACT или кто-то завёл тикет.

Андон: станок, который стоит без причины, не теряется. Через 2 минуты он
фиолетовый («нет тикета») и поднимается наверх, через 10 — мигает красным и
попадает в красную строку сверху, через 15 — уходит мастеру в телеграм. Обрыв,
который станок назвал сам, в андон не попадает, пока не затянется дольше 15 минут.
Пороги — в «Настройках». Внизу доски — «Скоро»: съём ткани и сход навоев на
ближайшие два часа.

Каждому монитору можно дать свой участок — 80 плиток с трёх метров не прочитать:

```
/wall?zone=D            весь ряд D
/wall?looms=D1-D20      участок
/wall?looms=D1,D5,J7    перечисление
```

На каждой плитке — обрывы за день и время простоя по ним: уток, основа, ворс и
отдельно ожидание оператора. По умолчанию берётся последний день с данными; для
разбора прошедшего дня или смены:

```
/wall?day=2026.09.12            за день
/wall?day=2026.09.12&shift=B    за смену B
```

В режиме разбора плитки выстраиваются по потерям на обрывах, а цвет показывает
КПД за этот день: красный — ниже 60 %, жёлтый — ниже 75 %, зелёный — выше.

### Карточки станков

```
http://<сервер>:8780/cards
http://<сервер>:8780/cards?day=2026.09.12&zone=D
```

Тот же набор, что в карточке DPA, но из данных FACT: модель станка, причина
останова по-русски и по-английски, оператор, OEE за смену и за сутки, обороты,
дизайн и код ткани, тикет, обрывы (WeftStop / WarpStopP / WarpStopG), остаток
основы в метрах и выработка — всего и по сменам A, B, C.

### Операторы из FACT

FACT сам пишет, кто стоял на станке: файл `factdata/operator/<день>.txt`,
строка на станок с `ope_name`. Расстановку можно не вводить руками:

```
python -c "import sys; sys.path.insert(0,'_app'); import people; print(people.import_assignments_from_fact('2026.09.12'))"
```

Сопоставление идёт по коду оператора (имена в FACT пишутся вразнобой:
«DILOROM41», «DILOROM 41», «SABOXAT30»). Проставленное вручную не затирается.
FACT знает оператора на сутки, а не на смену, поэтому расстановка ставится на
все три смены дня; на вкладке «Зарплата» её можно поправить.
 Смотреть можно без входа — монитор не логинится. Нажатие на
станок открывает тикет: выбрал «вызов электрика» — весь этот простой ушёл в
электрическую проблему. Заводить и разбирать тикеты можно только со входом
(право «тикеты»: администратор, мастер, оператор).

Тикеты заводятся сами, когда приложение видит живой FACT:

```
python _app\app.py --fact http://172.0.30.9
```

Без этого ключа приложение работает по зеркалу, и тикеты заводятся вручную —
иначе система завела бы тикеты на позавчерашние остановы из зеркала.

Вкладка «Тикеты» в приложении — список, разбор причин и потери по причинам за
сутки. Прежняя отдельная служба `_app\stopwatch` больше не нужна: всё в одном
приложении, одна база, один вход.

### Установка на сервер цеха

```
powershell -ExecutionPolicy Bypass -File _deploy\install_autostart.ps1 -Fact http://172.0.30.9
```

Приложение регистрируется заданием планировщика: стартует при включении сервера,
поднимается само после падения, работает без вошедшего пользователя. Адрес FACT и
порт записываются в `_app\config.json` — потом правятся там, а не в задании.

Резервная копия цеховой базы (тикеты, пользователи, операторы, назначения):

```
powershell -ExecutionPolicy Bypass -File _deploy\backup.ps1 -To \\server\backup\ceh -Schedule
```

Копия снимается через `VACUUM INTO` — безопасно на работающем приложении, —
каждый день в 03:30, хранится 30 дней. База станков не копируется: она
пересобирается из зеркала командой `rebuild_db.py`.

### Телеграм: сводка после смены и тревога

Два сообщения, оба мастеру, а не в отчётность:

- **после каждой смены** — КПД, выработка, куда ушёл простой, пять станков с
  наибольшими потерями и сколько тикетов остались без причины;
- **утром, когда смена C закрыла сутки** — итог за день: три смены рядом,
  причины простоя и худшие станки за сутки (выключается ключом `daily_digest`);
- **тревога**, если приложение перестало получать данные от FACT дольше
  получаса: доска в цехе в это время показывает последнее известное состояние,
  и без предупреждения ему верят.

Что нужно: бот у `@BotFather` (даст token) и chat_id группы мастеров — узнать
его можно, написав боту и открыв `https://api.telegram.org/bot<token>/getUpdates`.
Дальше скопировать `_app\config.example.json` в `_app\config.json` и вписать оба
значения. Проверка, ничего не отправляя:

```
python _app\notify.py --dry --shift 2026.09.11.A
```

Пробное сообщение в чат: `python _app\notify.py --test`.
Без настройки приложение работает как раньше — просто ничего не шлёт.

Токен бота — это пароль: кто его получил, тот пишет от имени бота в ваш чат.
Держите `config.json` на сервере, не кладите в общую папку и не копируйте в
резервные копии, доступные всему цеху.

### Если не получается войти

```
python _app\reset_password.py            # список пользователей
python _app\reset_password.py admin      # выдать новый временный пароль (из консоли)
```

Пароли хранятся только хэшем, старый узнать нельзя. Команда печатает новый
временный пароль и закрывает все сессии этого пользователя.

### Вход и права

При первом запуске создаётся администратор `admin` с временным паролем — он
печатается в консоль один раз и требует смены при первом входе. Пароли хранятся
только хэшем (PBKDF2-SHA256), восстановить их нельзя, можно задать новый.

| Роль | Что может |
|---|---|
| Администратор | всё, включая пользователей и ставку |
| Мастер | назначения на смену, тикеты, отчёты, выгрузка |
| Оператор | тикеты и просмотр |
| Наблюдатель | только просмотр |

Вкладки скрываются по правам, а запросы на изменение данных проверяются на
сервере — недоступное действие отклоняется, даже если обратиться к нему напрямую.

### Как определяется причина простоя

Технический сигнал станка важнее тикета: если станок сам назвал причину
(уток, основа, ворс, ложная кромка), она и остаётся. Тикет закрывает то,
что станок объяснить не может.

| Состояние | Условие | Причина |
|---|---|---|
| Off | обесточен + тикет ТОиР | ТОиР |
| Off | обесточен + тикет наладки | Наладка |
| Off | обесточен + тикет электрика | Электрическая проблема |
| Off | обесточен, тикета нет | Обесточен, причина не указана |
| Stop | есть сигнал (`0004`–`0019` уток, `2414` основа, `2415` ворс, `0001` кромка) | причина от станка |
| Stop | сигнала нет (`0027` ручной, `ffff` и прочие Other) | причина из тикета |

Коды берутся из данных FACT: за три дня `0027` (ручной останов) дал 2 267
остановов и 106 часов — это и есть тот простой, который раньше был без причины.

## Чего сейчас нет

- **Дизайн (MODEL)** не заполняется: артикул из кода ткани определяется неверно.
  Нужен справочник из технологических карт.
- **PPT, вес штуки, число панелей, номера пряжи** берутся из отчёта за 11.09.2026
  и привязаны к коду ткани. В FACT этих данных нет.
- **Зарплата по операторам** — не сделана: нужна ставка и правило привязки
  операторов к станкам по сменам.

## Как считаются показатели

Формулы восстановлены из макроса Toyota и сверены с отчётом FACT:

- КПД = время работы / (время работы + простой);
- обороты = 1000 × выработка (тыс. уточин) / время работы в минутах;
- время устранения обрыва = время останова − время ожидания оператора;
- среднее время устранения (MTTR) = время устранения / число обрывов;
- ворс — обрывы верхнего навоя, основа — нижнего.

Выходные смены, когда цех обесточен целиком, из сводных показателей исключаются:
иначе они занижают КПД (60,7 % против 68,4 % за тот же период).
