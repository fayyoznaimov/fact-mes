# История станков в приложении

Реализован раздел **Отчёты → История станков** (`/#history`). Он читает
локальные базы через защищённый `/api/machine_history`, без обращения к FACT.
Планирование по станкам и дням остаётся в разделе «План».

## Что доступно

- Календарные сутки либо смены A 07–15, B 15–23, C 23–07 следующего дня.
  Время — Ташкент, UTC+5, независимо от часового пояса браузера.
- Все станки (до 80), отдельный ряд или станок; масштаб шкалы 1×, 2×, 4×.
- Интервалы остановок из `stop_log`, цвет по причине Toyota. Короткие события
  доступны также в списке с постраничным просмотром по 50 строк.
- Начало, окончание, полная длительность, время внутри выбранного периода,
  код, причина, реакция и стиль из исходного события.
- Длинные остановки учитываются и после полуночи, включая начало несколькими
  днями раньше. Пересечения сохраняются в списке, но не удваивают общий простой.
- Тикеты MES показаны отдельной нижней дорожкой и списком причин/комментариев.
  Их длительности не складываются с остановками Toyota. Автоматической привязки
  тикета к конкретному событию станка нет.

## Ограничения источника

В `stop_log` отсутствуют отдельные события запуска и отметки полноты загруженных
файлов. Отсутствие остановки **не доказывает работу**. Промежутки помечаются как
«Работа · расчёт» только для завершённых смен, когда:

1. работа + простой в `shift_full` дают 480 минут с допуском 60 секунд;
2. объединённая длительность остановок согласуется с простоем смены с таким же
   допуском; исходные интервалы не пересекаются и нет некорректных строк.

Даже при совпадении это реконструкция, а не прямое событие Run. Все остальные
промежутки показаны штриховкой «Нет подтверждённого состояния»; будущее время
не включается ни в работу, ни в простой. В карточке станка есть сверка источников.
На копии за 14.09.2026 журнал и сменные итоги расходятся: восстанавливать работу
по этим данным нельзя. Для подтверждённой непрерывной истории Run/Stop требуется
дополнить сборщик сохранением переходов состояния и качества связи с источником.
В текущей правке сборщик и частота опроса не изменены.

## Нагрузка и доступ

Один запрос охватывает сутки или смену. Читаются события выбранных станков,
пересекающие окно полных смен, с учётом максимальной длины останова. Предел
60 000 событий/тикетов: при превышении API просит сузить выбор, не обрезает
историю молча. Кэш ограничен четырьмя ответами и 30 секундами; расчёты
последовательны. Соединения с обеими базами открываются только для чтения
и закрываются после запроса. Права соответствуют общему праву просмотра MES;
без входа/ключа чтения API возвращает 401. Новых операций записи нет.

## Проверка в изолированной копии

- `python -m py_compile` всех изменённых Python-файлов.
- `_tools/test_machinehistory.py`: 16 проверок на временных синтетических базах:
  переносы через полночь, многодневные остановы, границы, пересечения, неизвестное
  состояние, неполная смена, часовые пояса тикетов и валидация параметров.
- `_tools/e2e_test.py`: 94 проверки, 0 ошибок, включая закрытый доступ к истории,
  HTTP 400 для неверных параметров, баланс длительностей и ночную смену.
- Браузер: 40 станков, выбор D2/смены C, карточка конкретной остановки,
  постраничный список и масштаб; без ошибок JavaScript.
- Изолированный эксперимент с удвоенными событиями 40 станков: 80 станков,
  17 874 события за сутки, расчёт 0,374 с, JSON 5,54 МиБ. Это измерение одного
  запроса на синтетически расширенных данных, не приёмка всего MES под нагрузкой.

Рабочая папка и сервер цеха не изменены. Перед переносом — просмотр коммита
через `git log` и `git diff`; после переноса нужен перезапуск сервера (изменён Python).
