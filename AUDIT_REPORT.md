## Осталось исправить: приоритеты и предложения

### Высокий: временный пароль ограничивается только интерфейсом

`_app/auth.py:can` проверяет роль, но не `must_change`; маршруты сервера тоже
не ограничивают такую сессию. На отдельной тестовой базе пользователь admin
с `must_change=1` получил право `users`. Требование сменить пароль можно обойти
прямым обращением к API.

Предложение: пока пароль временный, разрешать только получение своей сессии,
выход и смену собственного пароля; запретить остальные действия на сервере.
Добавить проверки внутреннего и внешнего API с такой сессией.

### Высокий: при пустом PPT ломаются итоги Excel

`_tools/fill_template.ps1` пишет формулу `F*E*(C*24*60/D)` без проверки D (PPT).
В выгрузке за 2026.09.14 из тестовой копии обнаружены 42 ячейки с `#DIV/0!`,
включая J1 и J3. В D7 значение отсутствует, G7 делится на D7, а J1 суммирует G.
Это наблюдение на тестовых данных после сквозного теста, не проверка рабочего Excel.

Предложение: явно обозначать станки без PPT/веса/панелей как неполные данные,
не выдавать по ним правдоподобный ноль; итоговую эффективность сопровождать
показателем полноты. Формулы менять в создаваемой копии, не в оригинале xlsb.
Проверять ошибки формул в выгрузке: текущий e2e проверяет только наличие ZIP/XLSX.
Успешные 91/91 не означают, что показатели Excel корректны.

### Средний: неверная структура сообщения 1С даёт 500

Авторизованный POST `/api/v1/1c` с корректным actionType и
`data.productionOrders=[null]` воспроизвёл HTTP 500 без `success:false`.
`load_production_orders` вызывает `.get()` без проверки элемента;
`handle_1c` не перехватывает AttributeError для записи отказа в журнал сообщений.

Предложение: проверять типы конверта, каждого заказа, sizeInfo, technologies
и компонентов до записи; возвращать 400 с `success:false` и понятным указанием
ошибочного элемента. Сохранять отклонённый конверт в журнал 1С.

### Средний: импорт 1С фиксируется несколькими транзакциями

По коду `_app/integration.py` техкарты коммитятся раньше связок ткани, плана,
пересборки отчётов и сохранения исходных заказов. Ошибка последующего этапа
может оставить обновлённые техкарты при неуспешном ответе и старом архиве.
Это вывод из порядка операций; искусственный сбой после коммита не внедрялся.

Предложение: сохранять бизнес-данные сообщения и статус его обработки
атомарно; пересборку отчётов вынести в повторяемый этап с явным статусом.

### Средний: отсутствует ограничение времени чтения HTTP-тела

Проверка длины исправлена, но клиент всё ещё может объявить допустимую
положительную длину и перестать передавать байты. `_read_body` ждёт их без
таймаута, а ThreadingHTTPServer создаёт потоки для соединений.

Предложение: ограничить время чтения запроса и количество одновременных
обработчиков, отдельно сохранить длительные SSE-соединения мониторов.
Массовую проверку зависающих клиентов не запускал.

### Средний: таблица блокировок кэша растёт без ограничения

`_app/cache.py` ограничивает `_data`, но не удаляет ключи из `_locks`.
Воспроизведение на 1000 разных ключах: 400 значений и 1000 блокировок.

Предложение: ограниченный набор блокировок либо удаление с учётом ожидающих
потоков. Простое удаление занятой блокировки нарушит правило «один считает».

### Низкий: некорректная дата сессии может вызывать 500

`user_by_token` принимает ISO-дату без часового пояса, затем вычитает её из
даты с часовым поясом. На отдельной базе воспроизведён TypeError. При ошибке
соединение также не закрывается явным finally.

Предложение: отзывать сессии с недопустимыми/неполными датами, всегда закрывать
соединение; добавить тесты истечения и повреждённых временных меток.
