# Правила для ИИ-агентов (Claude Code, GPT/Codex)

В этом репозитории работают по очереди несколько агентов и человек. Эти правила —
общие для всех: прочитай их перед любой правкой.

## Перед началом и после работы

1. `git status` и `git log --oneline -10` — посмотри, что поменял предыдущий агент.
   Незакоммиченные чужие правки не перетирай: закоммить их отдельно или спроси.
2. Одна логическая правка — один коммит. Сообщение по-русски: что и зачем
   («Заправка: отбор пряжи по месту из справочника 1С»), а не «fix».
3. Историю не переписывай: без `push --force`, `rebase` и `reset --hard` по общим коммитам.
4. Перед коммитом: `python -m py_compile` изменённых .py; при правке сервера или
   интерфейса — сквозной тест (ниже).

## Чего нельзя

- **FACT (Toyota, 172.0.30.9) — только чтение.** Никаких записей и лишней нагрузки:
  частоту опроса задаёт `_app/collector.py`.
- **Оригинальный шаблон отчёта `.xlsb` не менять.** `_tools/fill_template.ps1` работает с копией.
- **Базы, зеркало FACT, отчёты, ключи в git не класть** — см. `.gitignore`.
  Живые ключи API есть в `postman/` (игнорируются), в код и документы их не копировать.
- **Пишущие проверки — только на песочнице**, не на рабочем сервере `:8780`.

## Где что

- `_app/` — сервер цеха (Python stdlib, `web.py`), интерфейс — один файл `ui.html`,
  доска мониторов — `wall.html`, приём 1С — `integration.py`, API — `api.py`.
- `_tools/` — отчёт по дням и Excel (`make_excel_report.py`, `fill_template.ps1`),
  база станков `fact.db` (пишет только сборщик).
- `ARCHITECTURE.md` — устройство системы, `METRICS.md` — метрики,
  `GOLIVE.md` — запуск в цеху, `README.md` — обзор.

## Сквозной тест

`_tools/e2e_test.py` — 70 проверок (права, все вкладки, заправка, справочник пряжи,
конверт 1С, план, Excel, скорость). Запускается на копии приложения:

1. скопировать `_app` и `_tools` (с базами) в `%TEMP%\fact_e2e`;
2. дополнительно скопировать `postman/order_1557.json` в такую же папку песочницы
   и справочник `13.mxl` в `_tools/fixtures/13.mxl` (эти локальные данные не коммитить);
3. в копии `_app/shop.db` завести сессию администратора и ключ 1С, записать их в
   `_app\e2e_secrets.json` копии;
4. `python app.py --port 8790 --mirror --no-collector` из `_app` копии;
5. `python e2e_test.py` из `_tools` копии; после — остановить и удалить копию.

Базы работающего приложения копировать через SQLite backup API с исходным
соединением `mode=ro`: простое копирование `.db` может потерять данные из WAL.
`config.json`, живые сессии и API-ключи не переносить в тестовый запуск.

## Предметная область (коротко)

Ткацкий цех полотенец, 40 станков Toyota (ряды D и J), смены A 07:00, B 15:00, C 23:00.
Штука Toyota — это ряд; полотенец = ряды × панели. PPT и вес штуки вносят в
«Заправке» вручную; дизайн, размер, GSM и пряжа с лотами — из техкарты 1С
изделия заказа (ключ техкарты — номер заказа + номенклатура). Вес штуки =
ширина × длина × GSM + надбавка на угар (настройка `weight_allowance_pct`).
Секунды 1С на ряд заложены с эффективностью 75 %.
