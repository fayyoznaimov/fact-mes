# Постепенный перенос существующего интерфейса на React

Перенос сохраняет внешний вид и поведение текущего HTML MES. Редизайн и новые
переходы из отчёта в причины остановов не входят в этот шаг. Первый экран —
производственный отчёт со всеми 45 колонками и существующими действиями.

## Устройство перехода

Python отдаёт по `/next/` исходную `_app/ui.html` с дополнительным модулем из
Vite manifest. Поэтому CSS, шрифты, оболочка, темы и диалоги остаются исходными.
React через portals управляет четырьмя областями отчёта: панелью управления,
таблицей, плитками итогов и полосой полноэкранного режима.

`ReportController` владеет запросами отчёта, подготовкой строк, фильтрами,
сортировкой и сохранением вида. Запросы отменяются, запоздавшие ответы отвергаются
по номеру поколения. При сбое остаются последние успешные данные и их дата.
`SetupDialog` владеет формой заправки, ручными значениями и формированием payload.
`ReportWorkflow` управляет периодом, проверкой и проведением документов заправки
и отчёта, а также сборкой и скачиванием Excel. `DocumentBody` и `period` сохраняют
исходную разметку; `http` обрабатывает ошибки API и истечение сессии.
При конфликте checksum серверная проверка показывается заново, отметка о прочтении
предупреждений снимается. Повторное проведение во время запроса блокируется.
`FactReportLegacy` — временный мост к подбору пряжи, журналу документов,
авторизации, уведомлениям и измерению липкой шапки.
`FactReactReport` принимает список дат и команды обновления от оболочки.
Исходный рендерер отключается только при установленном React-мосте. Основной
адрес `/` продолжает работать самостоятельно и служит эталоном сравнения.

Модули React разделяют подключение, описание колонок и правила отбора, ячейки,
таблицу и управление. Расчёты производства, API, сессии и права остаются в
Python и SQLite. Одновременная замена backend не нужна для этого переноса.

## Проверка совместимости

Vitest выполняет исходный рендерер из HTML в отдельном DOM и сравнивает с React
тексты, классы, подсказки, итоги, фильтры, сортировку, пороги и свёрнутые группы.
Дополнительно проверяются действия компонентов и подключение моста. HTTP-тест
проверяет, что оболочка отдаётся целиком и без изменений. Браузерная сверка нужна
для геометрии, переводчика, полноэкранного режима и диалогов.

Форма заправки, подтверждение её документа, отчёт за период и подтверждение
отчёта перенесены. Документы остальных разделов пока используют старые обработчики.
Подбор пряжи общий с табличной заправкой и сохраняет исходный обработчик.
Полный E2E на отдельной копии обязателен перед коммитом согласно `AGENTS.md`.

## Следующие шаги

1. Завершить проверки исходного отчёта на отдельной песочнице.
2. Переносить оставшиеся диалоги в отдельные React-модули с теми же
   контрактами и сценариями; удалять мост по мере замены его частей.
3. Аналогично переносить следующие разделы без изменения дизайна.
4. Подключить тесты и сборку frontend к установке кандидата Linux-выпуска,
   затем переключить основной адрес после проверки функционального равенства.

Интеграция 1С и переработка исторического учёта отложены. Новый UI собирается
отдельно; Node на рабочем сервере не требуется, если поставляется готовый `dist`.
