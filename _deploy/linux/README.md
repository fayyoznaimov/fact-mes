# MES на Linux

Python 3.12, стандартная библиотека. Linux-выгрузка создаёт самостоятельный
XLSX из тех же расчётных данных; внешний вид отличается от исходного XLSB.
Windows продолжает использовать существующий шаблон через Excel COM.

## Каталоги

- `/opt/fact-mes/releases/<commit>` — код конкретного коммита, владелец root.
- `/opt/fact-mes/current` — ссылка на активный выпуск.
- `/var/lib/fact-mes` — `shop.db`, `fact.db`, `factdata`, `run`, `logs`, `reports`.
- `/etc/fact-mes/config.json` — конфигурация, root:fact-mes, 0640.
- `/etc/fact-mes/service.env` — адрес, порт и режим службы.
- `/var/backups/fact-mes` — ежедневные копии SQLite и конфигурации, доступ
  служебному пользователю fact-mes; администратору — через sudo.

В каталоге выпуска `_app/shop.db`, `_tools/fact.db`, `_app/config.json`,
`_app/run`, `_app/logs`, `factdata` и `reports` — ссылки в каталоги выше.
Исходные базы переносятся через SQLite backup с `mode=ro`, сессии в новой
копии очищаются. Пароли пользователей и их настройки сохраняются.
Штатные имена баз, схема приложения и маршруты 1С остаются прежними.

## Режим до переключения цеха

```ini
MES_HOST=172.0.30.4
MES_PORT=8780
MES_SOURCE_ARGS=--mirror --no-collector
```

Пока Windows обслуживает цех и собирает Toyota, Linux использует перенесённый
снимок. Он не обновляется автоматически. Это предотвращает двойной опрос FACT
и расхождение записей при незавершённом переносе.

## Переключение

1. Согласовать остановку записей в старую MES и остановить её сборщик.
2. Сделать финальные backup обеих баз с `mode=ro`, перенести зеркало и
   необходимые настройки интеграции. Сохранить отдельную копию до миграций.
3. В `service.env` указать `MES_SOURCE_ARGS=--fact http://172.0.30.9`.
4. Перезапустить `fact-mes.service`; проверить свежесть Toyota и число станков.
5. Направить отправку 1С на `http://172.0.30.4:8780/api/v1/1c`, проверить
   подтверждение и журнал. Перенесённые хэши ключей сохраняют совместимость.
6. Только после этого открыть Linux для рабочих записей пользователей.

Не включать второй сборщик FACT одновременно с Windows. Telegram и исходящий
опрос 1С подключать после переключения, чтобы не дублировать действия.

### Сохранение прежнего адреса 1С

Для `http://172.0.30.107:8780/api/v1/1c` предусмотрен
`_deploy/windows_1c_relay.py`. После остановки старой MES он занимает её порт
и передаёт GET/POST этого маршрута в Linux, сохраняя Authorization, тело и
HTTP-статус. Остальные GET перенаправляют браузер в Linux. Старые открытые
вкладки перед дальнейшими правками нужно обновить.

Переадресатор устанавливается отдельно от рабочей папки цеха, в
`%LOCALAPPDATA%\FACT-MES-relay`, с ярлыком автозапуска текущего пользователя.
Он не собирает Toyota и не меняет базы. Для сохранения старого IP компьютер
Windows должен быть включён, пользователь — войти в систему. Убрать эту
зависимость можно, поменяв в 1С адрес на `http://172.0.30.4:8780/api/v1/1c`.
После этого переадресатор и его ярлык можно отключить.

## Обслуживание

```sh
sudo systemctl status fact-mes
sudo journalctl -u fact-mes -n 100 --no-pager
sudo systemctl restart fact-mes
sudo systemctl start fact-mes-backup.service
sudo systemctl list-timers fact-mes-backup.timer
curl http://172.0.30.4:8780/api/health
```

Таймер запускает backup в 02:15 по Ташкенту с задержкой до пяти минут.
Каждая база проверяется `PRAGMA quick_check`; каталог появляется только после
успешного копирования. Две базы копируются последовательно, общей транзакции
между ними нет. Автоматического удаления резервных копий нет: нужно следить
за местом и организовать вторую копию на другом диске или сервере.
Backup работает от fact-mes, чтобы служебные WAL/SHM-файлы не получали владельца
root. Базы открываются с mode=ro; для блокировок SQLite доступен каталог данных.

Восстановление: остановить службу, сохранить текущие базы отдельно, восстановить
обе базы и конфигурацию из выбранной копии, вернуть владельца `fact-mes`,
проверить совместимость версии кода, запустить службу и проверить `/api/health`.
